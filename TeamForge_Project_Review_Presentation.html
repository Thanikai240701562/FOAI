Problem Definition
2. Problem Statement & Combinatorial Complexity
The Core Problem

Given N registered student candidates possessing heterogeneous technical skill proficiencies, academic seniority levels, and availability commitments:

  • Objective: Construct an optimal partition into cohesive project teams of target size K.
  • Hard Constraints: Exact team size limits, pairwise member uniqueness (AllDiff), and collegiate event registration.
  • Multi-Objective Harmony: Maximize skill coverage, role specialization, senior-junior pairing, and sprint availability.
Combinatorial Explosion Challenge

The total possible team subsets across N candidates for size K follows:

C(N, K) = N! / [ K! × (N - K)! ]
  • For cohort N = 60, K = 4: 487,635 subsets per team!
  • For cohort N = 60, K = 6: 50,063,860 subsets!
  • NP-Hard Complexity: Exhaustive brute-force search crashes server response times.
  • Resolution: Classical AI heuristics (MRV + Forward Checking + Hill Climbing) cut search tree to sub-millisecond execution.

AI Engine Specifications
6. Classical AI Formulation: The CSP Framework
Variables (X)

Unfilled functional team role slots:

X = { V_1, V_2, ..., V_k }

  • V_1: Team Leader / Architect
  • V_2: Frontend / UI Engineer
  • V_3: Backend / Database Specialist
  • V_4: Classical AI & Algo Lead
Domains (D)

Eligible student pools filtered dynamically per role:

D(V_i) ⊆ { Candidate Students }

  • Skills matching required technical tags.
  • Active registration in target hackathon.
  • Pinned members locked by leader.
Hard Constraints (C)
  • Team Capacity: Exactly k assigned slots.
  • Pairwise Uniqueness (AllDiff): ∀ i ≠ j, V_i ≠ V_j (no duplicate allocations).
  • Event Enrollment: Must possess verified event registration record.
  • Bandwidth Threshold: Active team commitments < threshold.

AI Engine Specifications
7. Combinatorial Search Optimization: MRV & Forward Checking
Minimum Remaining Values (MRV) Heuristic

"Fail-First Principle" in Action:

  • At each recursive step, evaluate remaining domain sizes across all unassigned role slots.
  • Select the variable V_chosen with smallest domain: min |D(V_i)|.
  • Why It Matters: Highly specialized roles (e.g. classical algorithm specialist with only 2 candidates) are tackled first. If impossible, the search fails immediately without evaluating hundreds of frontend variations.
Forward Checking (FC) Constraint Propagation

Look-Ahead Pruning:

  • When candidate C is tentatively assigned to V_i:
  • Immediately prune C from domains of all remaining unassigned roles:
    D(V_j) ← D(V_j) \ { C } ∀ j ≠ i
  • Domain Wipeout Detection: If any remaining role's domain size becomes 0 (|D(V_j)| = 0), forward checking triggers an IMMEDIATE backtrack.

Heuristic Search
8. Heuristic Local Search & Multi-Objective Optimization
Hill Climbing with 1-Opt Candidate Swaps
  • CSP search provides a valid baseline; local search maximizes overall team harmony.
  • 1-Opt Neighborhood Exploration: Systematically evaluates swapping each unpinned team member with an available candidate in the pool.
  • Strict Gradient Ascent: Retains neighbor swap only if fitness strictly increases: S(A_neighbor) > S(A_current) + ε.
  • Convergence: Terminates when no single swap yields a higher score (local optimum plateau).
Multi-Objective Fitness Function S(Team)
S = W_skill·SkillCov + W_role·RoleCov + W_exp·ExpBal + W_avail·AvailScore + W_int·Interest
  • W_skill (0.35): Coverage of mandatory project skills (1-5 proficiency scale).
  • W_role (0.25): Full coverage across specified team roles.
  • W_exp (0.15): Academic year diversity & past verified project count.
  • W_avail (0.15): Declared weekly availability (Available=100%, Busy=50%).
  • W_int (0.10): Hackathon domain interest alignment.

Security & Compliance
14. Privacy-Preserving Architecture & Web Security
Zero-Retention Ephemeral Team Chat
  • Zero Persistent Database Storage: Unlike Discord or Slack, chat messages are deliberately NOT stored in MySQL tables.
  • In-Memory Rolling Buffer: Kept in rolling server memory with automatic TTL expiration.
  • Team-Bound Access Wall: Enforced by server-side verification: isUserMemberOf($teamId, $userId). Non-members receive 403 Forbidden.
Defensive Engineering Hardening
  • 100% Prepared SQL Statements: Emulated PDO prepares disabled; eliminates SQL injection risks.
  • Anti-CSRF Tokens: Cryptographic token validation on state-changing endpoints.
  • Session Regeneration: session_regenerate_id(true) on login prevents session fixation.
  • Output Sanitization: Context-aware escaping via htmlspecialchars().
